# Known API gaps, per feature

The console talks only to the fortius-backend API (mock mode was removed on
2026-10-12 when the app went live). Each feature lives in
`src/features/<f>/api/` as `contract.ts` (domain types), `<f>Api.http.ts` (the
wire mapping) and `<f>Api.ts` (what pages import). This table records what a
feature cannot do yet, or does differently from what a screen might suggest,
so nobody mistakes a gap for a bug or a bug for a gap.

Notes written before 2026-10-12 may still refer to the mock adapter; those
sentences describe history, not current behaviour.

Edit no longer offers "Dilepas". | dashboard | **A same-day date filter on `/deliveries` used to read as empty**, discovered live while wiring `drivers`' schedule: the server's `date` filter compares `lte` literally against midnight UTC of the given day, so `gte X, lte X` against `created_at` (a timestamp, not a plain date) excluded almost all of day `X` -- verified against the running service (a delivery at 16:52 UTC matched `gte` its own day but not `lte` it). `fetchDeliveries` here, and the same pattern in `reportApi.http.ts` and `transactionApi.http.ts`, now send an exclusive `lt` bound one day past `to` instead. Before this fix, `dailyDistributed`/`dailyTarget`/`lateDeliveries` on a live API build were reading against zero rows for "today" in practice. Composes financeApi.getAgingReport(), orderApi.getOrderTotals(), saApi.getSAList() and its own /deliveries fetches (today, yesterday, this month) rather than a new backend endpoint — every figure already had a real feature behind it once B2/B5/B6 landed. The dispatch rail's `hasSchedule` is false: no field for a stop's planned time of day exists anywhere in the schema, so stops position by real dispatch order instead of a fabricated clock, and `DispatchRail.tsx` stops drawing an hour ruler, a "now" line and a late verdict over a position that was never a real time. `getRecentAudit` always returns `[]` — nothing writes to `audit.audit_trails` on the real service, and the mock's own seed carries no rows either. |
